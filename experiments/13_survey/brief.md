# 調査依頼: 1ビット未満の重み圧縮 — 世界の最前線と、我々に足りないもの

## 我々がやったこと（実測済み・すべて実物の重みで検証）

対象: qwen3.5-4B / qwen2.5-coder-3B の GGUF から抽出した実重み。
指標: 出力誤差 = ‖Wx − Ŵx‖ / ‖Wx‖。

### 現在のレシピ
```
W ≈ A·B (ランク32〜64, 4bit, A·Bの間にアダマール回転) + 残差を積ベクトル量子化
残差VQ: k個(8〜32)の重みを1コードに、コードブックはk-means学習、
        グループ512要素ごとのスケールを8bitで量子化
+ チャンネル重要度スケーリング (W'=W·diag(imat^0.375), α=0.75相当)
+ コード列にエントロピー符号化
```

### 到達した数字
| 方式 | bit/重み | 出力誤差 |
|---|---|---|
| RTN 4bit（比較用） | 4.13 | 0.157 |
| RTN 2bit | 2.13 | 0.749 |
| 三値(BitNet風) | 1.71 | 0.674 |
| 我々の最良(薄い方) | **0.431** | 0.502 |
| 我々の最良(厚い方) | 1.39 | 0.366 |

### 効いた/効かなかった（実測）
- 効いた: 低ランク＋残差量子化(大)、スケールのビット削減(大)、k と辞書の拡大(中)、
  チャンネル重要度スケーリング(本物の活性化でのみ+5〜24%)、内側回転(+2%)、
  エントロピー符号化(3〜5%)
- 効かなかった: 全体回転(ベクトル量子化には有害)、文脈モデル(ゼロ)、
  低ランクと残差の交互精錬(ノイズの内側)、乱数コードブック(崩壊)
- 誤差補償(GPTQ): 実装は厳密OBQと15桁一致で正しいが、合成活性化では過学習して悪化。
  本物の活性化での再評価は未実施（imatrixは対角成分しか持たないため）。

### 重要な発見
合成活性化（1%のチャンネルを一律20倍）は、本物（上位1%が全体の2.8〜7.5%）と比べて
2〜6倍も集中が過剰で、活性化を使う手法の評価を系統的に反転させていた。
本物の活性化では前半テキストと後半テキストの重要度相関が0.958で、極めて安定。

## 聞きたいこと

1. **世界の最前線**: 1ビット未満（sub-1-bit）の重み圧縮で、現在いちばん強い手法は何か。
   AQLM, QuIP#, QTIP, PV-tuning, SqueezeLLM, HQQ, VPTQ, GPTVQ など具体名と、
   それぞれの核心的アイデア、達成しているビット数と品質を、分かる範囲で正確に。
   我々のレシピに欠けている構成要素はどれか。

2. **量子化後の微調整**: 量子化した状態のまま学習し直す手法（QAT, PV-tuning,
   知識蒸留による回復）は、1bit未満でどれくらい品質を戻せるのか。
   我々は一切の再学習をしていない。ここが最大の伸びしろか？

3. **評価の妥当性**: 我々は1層の出力誤差だけを見ている。
   層ごとの誤差がモデル全体のperplexityにどう伝播するか、
   誤差0.5の層を積み重ねたモデルは実際どうなるのか。目安があれば。

4. **速度**: 1bit未満表現を「復元せずに」計算する実装（ルックアップテーブル方式など）は
   現実的か。CPU(AVX2)やGPUでの既存実装はあるか。軽いだけでなく速くできるのか。

5. **我々が思いついていない切り口**: 上記以外に、同じビット予算でもっと品質を出す
   本質的に異なるアプローチはあるか。
