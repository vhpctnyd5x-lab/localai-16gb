## 1. 「1 ビット未満」表現として、積ベクトル量子化(PVQ) より本質的に強い符号化はあるか？

| 方式 | ビット/重み | 主な特徴 | 期待できる誤差改善幅 |
|------|------------|----------|----------------------|
| **PVQ (k‑means コードブック)** | b/k | 固定長コード → ルックアップテーブル(LUT) で復元不要（コードインデックス → 事前に計算済みの部分ベクトル） | 0.5‑0.8 bit で 0.6 前後の rel‑error（実測） |
| **製品量子化 (PQ)** | b/k (サブベクトルごとに独立コードブック) | サブベクトル間の相関を無視せず、各サブベクトルに専用コードブックを持つ | 同ビット数で PVQ より 10‑30 % 誤差低減が報告されることが多い（例: FAISS の PQ4‑8） |
| **畳み込み型コードブック (Block‑wise VQ with overlap)** | b/k | 隣接サブベクトル間にオーバーラップを持たせ、スライド窓でコードを共有 → 効果的に次元数を増やす | 同じビット数で誤差が 0.05‑0.1 程度改善（実験的） |
| **ハッシュベースのエンコーディング (e.g. HyperHash, Signed‑Random‑Projection + quant)** | log₂ |C|/k (C = ハッシュバケット数) | 重みを高次元のランダム投影後に量子化し、インデックスだけを保存。LUT は投影行列＋量子化テーブルで構成 | 理論的には JL‑lemma による誤差 bound が O(√(log |C|/k)) で、実装はビット演算だけで完結 |
| **混合精度＋スパースマスク (e.g. 0.5‑bit + 1‑bit スパース)** | 0.5 bit (値) + スパースオーバーヘッド | 大きい重みのみをフル精度で保存、残りは 0 または ±1 に丸める。マスクはビットベクトルで圧縮 | 実測で 0.5‑0.6 bit かつ rel‑error≈0.2‑0.3（SparseGPT 系） |
| **学習可能なスケーリング付き 2 値化 (Binary Weight Networks, BWN)** | 1 bit (符号) + スケールベクトル | 各出力チャネルまたはブロックごとにスケールを学習し、重みは符号のみ。スケールは 16‑bit か 8‑bit で保存 | 1 bit 未満にするにはスケールをグループごとに 1‑bit 量子化（例: Group‑wise BWN）が必要だが、誤差は 0.3‑0.4 前後になることが多い |

### 結論
- **製品量子化(PQ)** は PVQ の自然な拡張であり、同じビット数で誤差を 10‑30 % 低減できることが実証されています。実装はサブベクトルごとに小さな LUT（例: 2⁴＝16 エントリ）を持ち、インデックスを 4‑bit パックして SIMD/LLVM のベクトルロードで取り出すだけなので、**復元不要**（LUT から直接部分ベクトルを読み出す）です。
- **ハッシュベースのエンコーディング** は理論的に「情報量＝log₂|C|/k」ビットで表現でき、LUT は投影行列（固定）＋量子化テーブルのみ。実装はビット演算とテーブル参照だけで完結し、Apple Silicon の **AMX**（行列乗算専用ユニット）や Intel の **AVX‑512/VNNI** でも高速に行えます。
- **スパースマスク＋低精度値** は、実際の LLM 重みが heavy‑tail 分布であることを利用すれば、0.5 bit 前後で rel‑error≈0.2 まで持っていける可能性があります。マスクはビットベクトルとして圧縮し、popcnt 命令で高速に選択できます。

したがって、**「本質的に強い符号化」としては、製品量子化またはハッシュベースのランダム投影＋量子化が現在の実装よりも有望**です。両方とも LUT だけで復元不要であり、Apple Silicon/Intel Mac の SIMD/AMX/VNNI に乗せやすい構造です。

## 2. 出力誤差 0.6 前後を実用域（4bit 相当≈0.16）に近づける現実的な道筋はあるか？　あるいは原理的に無理なのか？

### 2‑1. 理論的下限（情報量・歪みトレードオフ）

- **レート・ディストーション理論**（ガウス前提）では、平均二乗誤差 D とビット率 R の関係は  
  \[
  R(D) \approx \frac{1}{2}\log_2\frac{\sigma^2}{D}
  \]  
  （σ² は重みの分散）。  
  例えば、σ≈1（float16 重みの標準偏差）とし、目標 D が 0.16²≈0.025（ rel‑error≈0.16）なら  
  \[
  R \approx \frac{1}{2}\log_2\frac{1}{0.025}\approx 2.3\text{ bit/weight}.
  \]  
  つまり、**情報論的には 2 bit/weight 未満でも 0.16 レベルの誤差は不可能ではない**。（ただし、実際の重み分布はガウスより重い尾を持ち、これがレートを多少上げる要因になる。）

- **実測値から見ると**、4bit (≈4.13 bit) で rel‑error≈0.009、2bit (≈2.13 bit) で 0.75 程度です。これは **レート・ディストーション曲線がかなり鈍い** ことを示しており、同じビット数で誤差を 4‑5 倍改善するのは容易ではありません。

### 2‑2. 現実的な改善策（段階的アプローチ）

| ステップ | 具体的手法 | 期待できるビット削減・誤差改善 | 補足 |
|----------|------------|-------------------------------|------|
| **A. ハイブリッド量子化の精緻化** | - 上位 0.5‑1 % の外れ値を 8‑bit で保存（スケール付き）<br>- 残りを **製品量子化 (k=4, b=4)** または **ハッシュ VQ** で 0.5‑0.6 bit/weight | 全体ビット数 ≈ 0.6‑0.7 bit/weight、rel‑error 0.3‑0.4 前後になることが多い（実験例: LLaMA‑7B 0.5 bit ハイブリッドで 0.35） | 外れ値の比率をチューニングすれば、過学習を抑えつつ精度を稼げる |
| **B. 学習済みコードブックの fine‑tuning** | - PVQ/PQ のコードブックを、少数のステップ（例: 10‑20 イテレーション）で **勾配降下** または **EM** で更新（重みは固定、コードベクトルのみ更新） | 同ビット数で誤差 10‑20 % 削減（例: 0.63 bit → rel‑error 0.48） | コードブック更新は CPU 側でオフラインに行い、推論時は固定 LUT のみ |
| **C. チャンネルワイズ・グループワイズ スケーリング** | - 各出力チャネル（または 128 要素グループ）に **学習スケール s** を 8‑bit で保存<br>- 重みは符号または 2‑値（{-1,+1}）のみ | スケール分のオーバーヘッドは 0.125 bit/weight (128要素あたり 1 個) に抑えられ、実質 1‑bit 重みで rel‑error≈0.2‑0.3 が報告されている（BitNet、BinaryBERT 系） | スケールをグループごとに 4‑bit 量子化すればオーバーヘッド 0.03 bit/weight にまで削減可能 |
| **D. スパース化 + 値圧縮** | - 重みの大きさで上位 5‑10 % を **4‑bit** で保存、残りを **0** または **±1** に丸める<br>- マスクは **ビットベクトル + ランレングス圧縮**（例: Roaring Bitmap） | 実効ビット数 ≈ 0.5‑0.6 bit/weight、rel‑error≈0.2‑0.3（SparseGPT、SPQR 系） | マスクのデコードは popcnt やベクトル比較で高速；Apple の AMX でもスパース行列乗算のサポートが検討中 |
| **E. エントロピー符号化の後段適用** | - インデックス列（PVQ/PQ コード、スパースマスク）に **ハフマン**または **算術符号** を掛ける<br>- ファイルサイズで 0.1‑0.3 bit/weight 削減が見込める | デコード時はテーブル参照＋ビットストリーム読み込みのみ；CPU 側で高速に実装可能（例: SIMD ベースの Huffman デコーダ） | 推論遅延への影響は数％程度に抑えられるが、ランダムアクセスが必要になるため、ブロックごとに独立符号化（例: 128‑要素ブロック）が必須 |

#### 現実的な目標
- **0.8 bit/weight 前後** で rel‑error≈0.2‑0.25 が達成可能だと考えられます（上記のハイブリッド＋スケーリング＋軽微なエントロピー符号化の組み合わせ）。
- **0.6 bit/weight** では、現状の手法では rel‑error≈0.4‑0.5 が限界で、さらに 0.16 まで持っていくには **情報量の理論的限界に近づく** 必要があり、そのためには **重みの構造をより強く仮定**（例: 低ランク+スパース、または畳み込み的共通基底）し、**その構造を学習してから量子化** するアプローチが必要になります（例: LoRA＋量子化、または Tensor‑Train 分解＋量子化）。

> **結論**：  
> 4bit 相当の誤差（≈0.16）に **1ビット未満** で到達するのは、**現在のフラットな重み行列に対する汎用量子化だけでは原理的に厳しい** と考えられます。ただし、**構造仮定（スパース、低ランク、ブロック共通基底）＋ハイブリッド量子化＋エントロピー符号化** を組み合わせれば、**0.6‑0.8 bit/weight で rel‑error≈0.2‑0.25** までは現実的に到達可能です。0.16 程度まで詰めるには、重みの **低ランク分解（例: SVD、Tensor‑Train）** や **事前学習された基底（例えば、LoRA アダプタ）** を用いた「基底量子化」が必要になるでしょう。

## 3. 過学習（キャリブレーションデータへのフィット）を、本物の活性化を採る以外の方法で緩和できるか？

### 3‑1. 過学習の原因
- **キャリブレーションサンプル数 (N=4096) が入力次元 (D=1024) に対して比較的少ない** → 経験共分散の推定がノイジー。
- **ヘッセ近似（対角またはブロック対角）が誤りを大きくすると、補償方向がノイズに敏感になる**。
- **活性化の分布が実際のテキストと乖離している**（t 分布＋人工外れ値） → 補償がその人工的な外れ値に過剰適合。

### 3‑2. データに依存しない・または依存が薄い手法
