# 検討依頼: ローカルLLMの重みを「1ビット未満」で表現する

## 設定

- 対象は実物の重み行列 W (4096×1024, float16)。qwen3.5-4B の GGUF から抽出。
- 評価指標は出力誤差 rel = ‖Wx − Ŵx‖_F / ‖Wx‖_F。低いほど良い。
- 活性化 x は現時点では**合成**（自由度4のt分布、1%のチャンネルを20倍にして外れ値を模擬）。
  較正用と評価用は別サンプル。本物の活性化はまだ採れていない。
- ビット数はスケール等のオーバーヘッド込みで換算している（fp16スケール1個/128要素 = 0.125bit/重み）。

## 実装済みの方式

1. RTN: グループ(128要素)ごとの absmax スケールで整数丸め。
2. 三値: {-1,0,1} + 平均絶対値スケール（BitNet風、log2(3)=1.585bit）。
3. 積ベクトル量子化(PVQ): 連続する k 個の重みを1組にし、2^b 個の学習済みコードのどれかに割り当てる。
   1重みあたり b/k ビット。コードブックは k-means (8反復, 12万サブベクトルで学習)。
4. 誤差補償(GPTQ): 列を1本ずつ丸め、その誤差をヘッセ行列に基づいて右側の未処理列へ流す。

## 実測結果（出力誤差、低いほど良い）

| 方式 | bit/重み | 出力誤差 |
|---|---|---|
| RTN 8bit | 8.13 | 0.0088 |
| RTN 4bit | 4.13 | 0.157 |
| RTN 2bit | 2.13 | 0.749 |
| 三値 | 1.71 | 0.674 |
| PVQ k=4,b=4 | 1.13 | 0.586 |
| PVQ k=8,b=6 | 0.88 | 0.642 |
| PVQ k=8,b=4 | 0.63 | 0.777 |
| PVQ k=16,b=8 | 0.56 | 0.711 |
| PVQ 乱数コードブック k=8,b=4 | 0.63 | 0.971 |
| ハイブリッド(上位3%を8bit + PVQ) | 0.86 | 0.712 |

## 誤差補償(GPTQ)に関する重要な観測

実装の正しさは検証済み：小規模問題で「毎ステップ逆行列を再計算する厳密OBQ」と
出力誤差が15桁一致した。数学の向きは正しい。

その上で：

- **較正データ自身で測ると、GPTQは確かにRTNより良い**（4bit: 0.1357 vs 0.1441、2bit: 0.7307 vs 0.7525）。
- **別サンプルで評価すると逆転して悪化する**（4bit: 0.199 vs 0.157、2bit: 0.874 vs 0.723）。
- 活性化の相関を強めると悪化幅が拡大する（2bit: 1.43 まで悪化）。
- クリップ飽和率は 0.03% で無視できる。補償後の重みの振れ幅も中央値で1.1倍程度。

つまり**較正データへの過学習**が起きている。較正サンプル数は4096、入力次元は1024。

## 聞きたいこと

1. 1ビット未満の表現として、いま試している積量子化より本質的に強い符号化はあるか。
2. 出力誤差0.6前後を、実用域（4bit相当=0.16程度）に近づける現実的な道筋はあるか。
   それとも1ビット未満で実用精度は原理的に無理で、狙う場所が違うのか。
3. 上の過学習を、本物の活性化を採る以外の方法で緩和できるか。
4. コード番号列にエントロピー符号化（ハフマン/算術符号、文脈モデル）を上乗せして
   実効ビット数をさらに削る案を検討中。これは筋が良いか、落とし穴は何か。
